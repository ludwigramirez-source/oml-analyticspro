   ✓ Verifica que la configuración funciona correctamente

   .\apply_timezone_migration.ps1 -Environment development

   Mismo script que el anterior pero para Linux/Mac

   Primero dale permisos:
   chmod +x apply_timezone_migration.sh

   Uso:
   ./apply_timezone_migration.sh --environment development
   ./apply_timezone_migration.sh --environment production --force


4. restart_docker.ps1 (PowerShell - Windows)
   ----------------------------------------------------------
   Script simple para solo reiniciar Docker sin verificaciones

   Uso:
   .\restart_docker.ps1 -Environment development
   .\restart_docker.ps1 -Environment production

================================================================================
RESUMEN DE LA MIGRACIÓN
================================================================================

CAMBIO PRINCIPAL:
-----------------
GMT-5 (Colombia, Perú, Ecuador) → GMT-6 (Nicaragua, Costa Rica, El Salvador)

IMPACTO:
--------
- Todos los timestamps en reportes mostrarán 1 hora menos
- Los datos en la base de datos NO cambian
- La conversión es en tiempo real al consultar datos
- Los filtros por fecha siguen funcionando correctamente

ARCHIVOS MODIFICADOS:
---------------------
1. .env - Variable TIMEZONE_OFFSET=-6
2. backend/analytics/config.py - Configuración centralizada
3. backend/analytics/services/call_analytics.py - Conversión de timestamps
4. backend/analytics/services/agent_analytics.py - Conversión de timestamps
5. docker-compose.dev.yml - Variable de entorno
6. docker-compose.prod.yml - Variable de entorno (pendiente en producción)

VERIFICACIÓN:
-------------
Ejecuta esta query en PostgreSQL para comparar:

SELECT
    id,
    time AS time_original,
    time AT TIME ZONE 'America/Managua' as time_gmt6
FROM reportes_app_llamadalog
ORDER BY time DESC
LIMIT 5;

La columna time_gmt6 debería mostrar 1 hora menos que time_original
(si la BD está en GMT-5).
